# Upgrading to 2.1.0

Version 2.1.0 supports Nodemailer 6 through 10. It also fixes transport defaults,
plugin execution, reset behavior, and error handling. See the
[changelog](../../CHANGELOG.md) for the complete list.

## Install

Update the mock development dependency:

```sh
npm install --save-dev nodemailer-mock@^2.1.0
```

Keep your application's Nodemailer dependency within the supported peer range.
Choose a Node.js version supported by that Nodemailer release. Nodemailer 10
bundles TypeScript declarations; earlier supported releases need a matching
`@types/nodemailer` package in TypeScript projects.

## TypeScript annotations

Use the exported `NodemailerMockTransporter` or `Transporter<MockSentMessageInfo>`
to annotate a mock transporter:

```typescript
import nodemailerMock, { type NodemailerMockTransporter } from 'nodemailer-mock';

const transport: NodemailerMockTransporter = nodemailerMock.createTransport();
```

`MockSentMessageInfo` describes the mock's existing placeholder results. Its
`envelope` is a string, and `response` can be an `Error` for a failed mock send.
Use `mock.getSentMail()` to inspect message data in assertions. The result fields
are placeholders for SMTP results. Standard Nodemailer plugins and failure-check
functions still work with the mock.

## Behavior to check in your tests

- `createTransport()` accepts omitted options and SMTP URLs. Message defaults from
  the second argument now apply, with per-message values taking precedence.
- Built-in Nodemailer processing runs alongside the mock's plugin bookkeeping.
  User plugins run only while `setUnmockedUsePlugins(true)` is active, including
  plugins registered before the flag changes.
- `reset()` restores mocked verification and close behavior, disables user plugins,
  and cancels scheduled idle changes. It retains transporters, their registered
  plugins, individual close counts, and current idle states.
- `getMockFor(nodemailer)` uses the supplied module for underlying transports and
  delegated verification and close calls.
- A failed mocked verification no longer supplies a success value to its callback.
  Errors thrown by a failure check are preserved; other thrown values are wrapped
  in an `Error` with the original value as `cause`.
- Nodemailer 10 can resolve CommonJS and ESM imports to different entry points.
  When using `node:test` module mocks, register both resolved entry points as shown
  in the [README](../../README.md#example-using-nodetest).
